`aweXpect` is a fluent assertion library for .NET. It turns test verifications into readable sentences and produces
failure messages that explain in plain English what was expected and what actually happened.

```csharp
await Expect.That(message).IsEqualTo("It's a compliment");
```

```text title="Failure message"
Expected that message
is equal to "It's a compliment",
but it was "It's a complement", which differs at index 12:
           ↓ (actual)
  "…a complement"
  "…a compliment"
           ↑ (expected)
```

## Why aweXpect?

<Tabs groupId="aweXpectFeatures">
<TabItem value="async" label="Async-first" default>

Every expectation is awaited. The same fluent chain works for sync values, `Task`, `IAsyncEnumerable`, exceptions and
HTTP responses (with the separate [aweXpect.Web](https://github.com/aweXpect/aweXpect.Web) package): there is no
parallel `…Async()` API to remember.

```csharp
// Plain value
await Expect.That(result).IsEqualTo(42);

// Task<T>
await Expect.That(_users.GetAsync(id))
    .Satisfies(u => u.IsActive);

// IAsyncEnumerable<T> - the cancellation token flows through the stream
await Expect.That(_orders.StreamAsync())
    .Contains(o => o.IsPriority)
    .WithCancellation(cancellationToken);

// Delegate that throws
await Expect.That(() => _payments.ChargeAsync(-1m))
    .ThrowsExactly<ArgumentOutOfRangeException>();
```

Because the chain is awaited, `Because(...)` and `WithCancellation(...)` attach once at the end instead of being
threaded through every method. Multiple expectations compose directly via `Expect.ThatAll(...)`, without a
thread-static assertion scope.

</TabItem>
<TabItem value="performant" label="Performant">

<TabItem value="extensible" label="Extensible">

The [`aweXpect.Core`](https://www.nuget.org/packages/aweXpect.Core) package is intentionally kept stable so extensions
don't fight over versions. Add expectations for any type with extension methods on `IThat<TType>`:

```csharp
public static AndOrResult<Track, IThat<Track?>> IsRadioFriendly(
    this IThat<Track?> subject)
    => new(subject.Get().ExpectationBuilder.AddConstraint((it, grammars)
            => new IsRadioFriendlyConstraint(it, grammars)),
        subject);

// usage
await Expect.That(track).IsRadioFriendly();
```

The full walkthrough is at [Extending aweXpect](./11-extending/index.md).

</TabItem>
<TabItem value="frameworks" label="Any runner">

```csharp no-compile
[Fact]        // xUnit
[Test]        // NUnit / TUnit
[TestMethod]  // MSTest
public async Task IsActive()
    => await Expect.That(user.IsActive).IsTrue();
```

xUnit (v2 and v3), NUnit (v3, v4 and v5), MSTest and TUnit are detected automatically: a failure usually throws the
assertion exception of the test framework, see
[test frameworks](./03-how-it-works/09-test-frameworks.md#failed-expectations) for the exact types. `Fail` and `Skip`
[fail or skip a test](./03-how-it-works/09-test-frameworks.md#failing-a-test) without an expectation.

</TabItem>
<TabItem value="aot" label="Native AOT">

`aweXpect` and `aweXpect.Core` are trimmable and AOT compatible for `net8.0` and later, so a test project can be
published with Native AOT:

```xml title="Tests.csproj"
<PropertyGroup>
  <PublishAot>true</PublishAot>
</PropertyGroup>
```

Equivalency and event recording need the members and events of your types. A source generator that ships with the
`aweXpect` package registers them for each call site when your project is compiled, so they work without reflection. A
comparison or recording of a type the generator could not see fails with an error that names the type and tells you
how to register it, instead of silently verifying less.

The details are in [Native AOT and trimming](./03-how-it-works/08-native-aot.md).

</TabItem>

## Migrating from another assertion library?

The [aweXpect.Migration](https://github.com/aweXpect/aweXpect.Migration) analyzer ships code-fix providers that rewrite
most FluentAssertions and `xunit.Assert` call sites for you. See the [migration guide](/aweXpect/migration) for the full
walkthrough.
