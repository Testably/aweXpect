# Contributor guide

## Pull requests

**Pull requests are welcome!**  
Please include a clear description of the changes you have made with your request; the title should follow
the [conventional commits](https://www.conventionalcommits.org/en/v1.0.0/) guideline.
All code should be covered by unit tests and comply with the coding guideline in this project.

### Technical expectations

As a framework for supporting unit testing, this project has a high standard for testing itself.  
In order to support this, static code analysis is performed
using [SonarCloud](https://sonarcloud.io/project/overview?id=Testably_aweXpect) with quality gate requiring to

- solve all issues reported by SonarCloud
- have a code coverage of > 90%

Additionally each push to the `main` branch checks the quality of the unit tests
using [Stryker.NET](https://stryker-mutator.io/docs/stryker-net/introduction/).

## Building and testing

`dotnet build aweXpect.slnx` builds everything. The build pipeline in `Pipeline/` runs the same steps as the CI
workflows, e.g. `./build.ps1 UnitTests` (or `./build.sh UnitTests`).

### Unit tests

The unit tests (`Tests/aweXpect.*.Tests`, except `aweXpect.Api.Tests`) run on [TUnit](https://tunit.dev). Each test
project is an executable of the Microsoft.Testing.Platform, so run it with `dotnet run`, or from an IDE that supports
this platform. `dotnet test` does not run these projects.

```shell
# All tests of a project for one target framework
dotnet run --project Tests/aweXpect.Tests -f net8.0

# The tests of one class: the filter is /<assembly>/<namespace>/<class>/<test>, nested classes are joined with "+"
dotnet run --project Tests/aweXpect.Tests -f net8.0 -- --treenode-filter "/*/*/ThatString+IsEqualTo+Tests/*"

# A single test
dotnet run --project Tests/aweXpect.Core.Tests -f net8.0 -- --treenode-filter "/*/*/SkipTests/Test_ShouldThrowException"
```

Use `[Test]` for a test, `[Arguments(...)]` for its inline data, `[MethodDataSource(nameof(...))]` for data from a
member, and `[AutoArguments]` (from `Tests/Shared`) for values generated by AutoFixture. TUnit runs the tests of a
class in parallel: a test that changes process-wide state needs `[NotInParallel]`.

### Slow tests

Tests that take long are marked with `[Explicit]` and `[Category(TestCategories.Slow)]`. A run without a filter leaves
them out; the pipeline runs them in a second step after the other tests. Locally, run them through a filter:

```shell
# All slow tests of a project
dotnet run --project Tests/aweXpect.Docs.Tests -f net8.0 -- --treenode-filter "/*/*/*/*[Category=Slow]"

# A single explicit test, or all tests of an explicit class
dotnet run --project Tests/aweXpect.Core.Tests -f net8.0 -- --treenode-filter "/*/*/EquivalencyComparisonTests/WhenNestingExceedsTheStack_ShouldContinueOnAFreshStack"
dotnet run --project Tests/aweXpect.Generators.Tests -f net8.0 -- --treenode-filter "/*/*/ComparisonTypeParityTests/*"
```

TUnit only runs explicit tests when every test that the filter matches is explicit, so always use both attributes
together. The first slow test of a project also needs the project in `ProjectsWithSlowTests` in
`Pipeline/Build.UnitTest.cs`.

### Other tests

`aweXpect.Api.Tests` (the accepted public API, on NUnit) and the VSTest projects under `Tests/Frameworks` run with
`dotnet test <project>`.
